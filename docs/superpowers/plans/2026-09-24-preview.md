# Preview Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `placemat preview <script>` places the board (reusing what it can) and draws the plan to SVG, and PNG through an external converter, with layers for links, pockets, unplaced parts, copper and congestion - no board write, DRC or render.

**Architecture:** `congestion.rudy` keeps its grid. A pure `preview.py` turns a Plan into SVG text. The runner's preparation (cached generation, settings, fab profile, script, board) moves into one function both `run` and `preview` call. `cli.py` adds the command; the PNG comes from `[preview] converter`, run with `subprocess`.

**Tech Stack:** Python 3 standard library only; `rsvg-convert` (external, optional).

**Spec:** `docs/superpowers/specs/2026-09-24-preview-design.md`

## Global Constraints

- No new Python dependencies; the SVG is written by placemat; the PNG only through the configured command.
- Deterministic SVG: fixed number formatting, sorted iteration.
- A preview never writes a run record, `latest.json` or `best.json`.
- A missing or failing converter is not an error: the SVG stays, the reason is printed, exit 0.
- Generic wording (no module, part or board names) in src, skill and migrations; plain ASCII; no attribution lines.

### Task 2: The drawing

**Files:** Create `src/placemat/preview.py`; test `tests/test_preview.py`.

**Interfaces - produces:** `draw(plan, faces=("front", "back"), heat=True, links=True, copper=True, title="") -> str`.

- [ ] Failing tests (pure, synthetic board with a keepout, a pocketed part, an unplaced part, two limited links - one within, one over - a track and a via):
  1. the SVG parses (`xml.etree`), has one `<g class="face front">` and one `face back`, and the back group's transform mirrors x;
  2. one `class="pad"` element per placed pad on its face; one `class="courtyard"` per placed part;
  3. the link within its limit is `class="link ok"`, the one over is `class="link over"`;
  4. the pocketed part has `class="pocketed"`; the unplaced part's key appears in `class="unplaced"` text;
  5. with `heat=True` a `class="heat"` group exists and a `class="worst"` ring sits at `plan.rudy.worst_at`; `heat=False` has neither; `links=False` and `copper=False` drop their groups;
  6. the same plan gives the same text twice.
- [ ] Implement: an SVG builder (numbers `%.3f`, attributes in fixed order); per face a panel group; board (outline polygon from `plan.shape`/`plan.outline`, cutouts; frame dotted when `not plan.draw_outline`), keepouts (`plan.keepouts` and the occupancy's reservations), heat (cells with utilisation > 0.05, colour by value), parts (from `plan.occupancy.items` for placed steps: pads of that face, courtyard, body box, silk polygons transformed by the occupancy's transform, the reference text), copper ops (Track, Via, Zone/Pour outlines), links (`plan.links` with `achieved_mm` and `limit_mm`), pocketed (from `plan.pocketed`), unplaced list (steps with no placement, kind part/cell/block), legend, grid and mm labels.
- [ ] Tests, suite, commit.
