# Pad Vias Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `board.vias(net, PadRef(...), pitch=, size=, drill=, inset=)` fills a pad with a square grid of vias, in the part's frame, resolved when the part is placed.

**Architecture:** A copper intent like `board.via`'s. Its plan reads the pad's placed land polygons from the occupancy, lays a square grid centred on the pad's box, turned with the part, and keeps each point whose via circle (grown by `inset`) lies wholly inside one land (`geometry.poly_within`). The vias join `ctx.planned_vias` so a later FreeSpot keeps clear of them.

**Tech Stack:** Python 3.12, pytest; one KiCad DRC test on the breakout board.

**Spec:** `docs/superpowers/specs/2026-09-27-pad-vias-design.md` (approved 2026-09-27)

## Global Constraints

- Defaults: `size`/`drill` the net class's via (`netclass.via_diameter`, `via_drill`); `pitch` = `max(size, drill + geometry.hole_to_hole)`; `inset` = 0.
- A `pitch` below `drill + geometry.hole_to_hole` is refused at declaration, naming the rule.
- A pad no via fits in: a finding naming the pad and the via; nothing drawn.
- The step note says how many vias were placed and that they are in the pad (filled or plugged at the fab).
- Generic wording; plain ASCII; commits carry no tool or session reference; bench before placement commits.

## Review Focus

1. A pad on a part turned 90 or 180 degrees: the grid turns with it (same vias relative to the pad). Test in Task 1.
2. A round pad: only points whose whole via is inside. Test in Task 1.
3. A pin of several lands: each land is filled, no via straddles two. Test in Task 1.
4. A FreeSpot via declared after `board.vias` on a neighbouring pad keeps the hole-to-hole rule from the grid. Test in Task 1.
5. KiCad DRC on a filled pad adds no violation. Test in Task 2.

- [ ] **Step 3: Implement** `Board.vias(self, net, pad, *, pitch=None, size=None, drill=None, inset=0.0, priority=Priority.DEFAULT, why="")`:

```python
        name = self.geometry.require_net(net)
        nc = self.geometry.netclass(name)
        s = float(size) if size is not None else (nc.via_diameter if nc else self.via_size)
        d = float(drill) if drill is not None else (nc.via_drill if nc else self.via_drill)
        floor = d + self.geometry.hole_to_hole
        step = max(s, floor) if pitch is None else float(pitch)
        if step < floor - 1e-9:
            raise ValueError("%s: vias %.2f mm apart break the hole-to-hole rule (%.2f mm hole plus %.2f): "
                             "%.2f mm at least" % (name, step, d, self.geometry.hole_to_hole, floor))
        owner, number, _, _ = self._pad_ref(pad)

        def plan(ctx):
            occ = ctx.occ
            lands = [sh.poly for sh in occ.items[owner].shapes if sh.label == number and sh.kind in ("pad", "through")]
            rot = occ.items[owner].reference.rotation
            box = Box.union([Box.of_points(p) for p in lands])
            c = box.center
            n = int(max(box.width, box.height) / step) + 2
            from .lock import _turn
            vias = []
            for i in range(-n, n + 1):
                for j in range(-n, n + 1):
                    ox, oy = _turn((i - (n % 2 == 0) * 0.5) * step, (j - (n % 2 == 0) * 0.5) * step, rot)
                    at = Location(round(c.x + ox, 6), round(c.y + oy, 6))
                    ring = circle_polygon(at, s / 2.0 + inset, 24)
                    if any(poly_within(ring, land) for land in lands):
                        vias.append(Via(name, at, d, s))
            if not vias:
                ctx.notes.append("vias %s: no via fits in %s.%s (%.2f / %.2f mm, %.2f mm inset)" % (
                    name, owner, number, s, d, inset))
                return []
            ctx.planned_vias += vias
            return vias
        return self._copper_intent("vias %s" % name, net, priority, plan, _refs_in([pad]), why)
```

The grid is centred so that an even count straddles the centre and an odd count has a via on it: pick the offset set per axis from the count that fits the pad along that axis (compute `nx`, `ny` from the land's extent in the part's frame and centre `(k - (nx - 1) / 2) * step`), rather than the single `n` above - the test's 4 x 4 grid pins this. The step note: `_plan_copper`'s per-intent notes (see how `board.via` surfaces "nowhere") gain "%d via(s) in the pad: filled or plugged at the fab".
