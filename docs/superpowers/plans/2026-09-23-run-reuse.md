# Run Reuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A run replays the previous run's steps up to the first step whose inputs changed, and resolves from there, byte-identical to a fresh run.

**Architecture:** `src/placemat/reuse.py` holds the canonical forms and hashes (a context key, a chained step key) and the record format. `Board.resolve(reuse=...)` computes each step's key as it goes; while it matches the previous record it replays the recorded step - its commits, findings, seed counts and pocket flag - instead of calling `_settle`, and it records every step it resolves. The runner reads the latest run's `reuse.json` and writes its own.

**Tech Stack:** Python 3, pytest, hashlib, json.

**Spec:** `docs/superpowers/specs/2026-09-23-run-reuse-design.md`

## Global Constraints

- A replayed run is byte-identical to a fresh run: steps, notes, findings, copper, the written board.
- A key can only be wrong by being too cautious: anything that can change a step's result is in its key or the context.
- Deterministic, pure Python, no new dependencies; plain ASCII; no attribution lines; benchmark tally in each commit.
- Tests run as `.venv/bin/python -m pytest -q > $S/out.txt 2>&1; echo $?`.

### Task 1: Keys

**Files:** Create `src/placemat/reuse.py`; test `tests/test_reuse_keys.py`.

**Interfaces - produces:**
- `canonical(obj) -> str`: a stable text form of a declaration value - dataclasses by field, enums by value, floats by `repr`, Footprints and cells by their key, tuples and frozensets sorted where order does not matter.
- `context_key(board) -> str`: sha256 over the tool version, the generated board's bytes digest, the settings JSON, the fab profile JSON, and the canonical form of every non-placement declaration (copper intents, planes, free nets, keepouts, cutouts, labels, rules, outline, size, cutouts, web); with the solve on, every placement intent and link as well.
- `step_key(previous: str, intent, links) -> str`: sha256 of the previous key, the intent's key and canonical form, and the canonical form of the links on its pads, sorted.

- [ ] Failing tests: the same board twice gives the same context and step keys; changing a keepout, a setting, the fab profile or the board bytes changes the context; changing one intent's `radius` changes that step's key and every later one but no earlier one; a link on another item's pads leaves a step's key alone and one on its own pads changes it; with the solve on, any intent change changes the context.
- [ ] Implement; tests pass; suite; commit.

### Task 2: Record and replay in the resolve

**Files:** Modify `src/placemat/layout.py` (`resolve(progress=None, reuse=None)`, `place_one`, `Plan.reuse`); test `tests/test_reuse_replay.py`.

**Interfaces:**
- Consumes Task 1.
- Produces `Plan.reuse: dict` - `{"context": key, "steps": [{"key", "step", "commits", "findings", "seeded", "pocketed"}], "reused": N, "first_change": item or None}` - with Steps and Placements in a JSON-safe form, and `Step.from_json`/`to_json` (and the same for `Placement`).

- [ ] Failing tests (pure, synthetic boards like `tests/test_seeded_pocket.py`'s):
  1. resolving twice with the first plan's `reuse` given replays every step, and the second plan's steps, findings, copper and occupancy placements equal the first's;
  2. changing the third searched item's declaration replays the steps before it and gives the same plan as a fresh resolve of the changed board;
  3. a changed order (a new `priority=` on a later item that moves it first) breaks the chain at the first step it changes;
  4. a block replays with its satellites committed where the fresh run commits them;
  5. `reuse` whose context differs replays nothing.
- [ ] Implement: during `place_one`, compute the step key; if it equals the record's key at the same position and every earlier step replayed, replay; else resolve, and stop replaying for the rest of the run. Recording wraps `_settle`: `occ.commit` is observed for the duration, and `plan.findings`, `plan.seeded_by_net`, `plan.pocketed` are diffed before and after. Replaying applies the recorded commits in order, extends the findings, adds the seed counts, restores the pocket flag, and returns the Step rebuilt from JSON. `plan.solve` is recorded in the context and restored when the solve's step is replayed.
- [ ] Tests pass; suite; bench (same on 32); commit.
