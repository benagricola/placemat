# Studio view audit (v0.99.29, main @ 2ea9ba66)

Views: (a) the studio's chosen script; (b) a followed command (Latest, or a command opened from the picker or the Runs tab); (c) a past run, explore or route record. "(a)+view" means a script is chosen and a (b)/(c) view of a script is open on top of it. That view may be of the chosen script or of a different one.

Bug 3 (the code view opens empty from a source link) is excluded. Source links in cards, steps and findings all go through `openScript`, so they are bug 3.

Evidence:
- **verified**: run in a harness (scratchpad `harness.py`, `harness2.py`). The harness stages a copy of the `usb5v` fixture in a temp dir and calls the Studio methods behind each endpoint, with no kicad and no server.
- **code**: traced end to end in the source, not run.

### Not script related but seen while tracing (c)

- An explore view drawn from the run's board in the "moved" case reads `layout.kicad_pcb` through `board_doc`, even when the run kept a `plan.json`. Its keepouts, reservations and the plan's copper are therefore not drawn.
- The cause is that `_run_doc(..., findings=False)` skips plan.json: `studio.py:1902-1911`.
