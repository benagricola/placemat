# Roadmap to 1.0: phases, one score, refine, the loop

Status: draft for review, 2026-10-06. This is the overarching plan for the four 2026-10-06 designs, on the 0.100.x
release line; the user cuts 1.0 once all of it is merged.

## Why

On the fairing core, placemat got a complex board to about 90% routed, but the last stretch stalled for four reasons:

- **Slow judgement:** each placement change cost a full resolve, and each explore variant cost minutes.
- **A frozen board:** locks pinned whatever an explore once chose.
- **Five objectives:** placements were made against one score and judged by another.
- **Declared power legs:** declared copper over-constrained placement, and routing had no order the project controlled.

Agents also had to know a long sequence of commands, and acted only on findings that changed the board.

The work replaces that with one loop: place, refine, route the phases, score, refine again. It uses one score and runs
as one command, and the script's and the capture's constraints are the only things that hold an item.

## Work outside placemat

- **KRT fork** (benagricola/KiCadRoutingTools): the `--connections` option routes only given pad pairs, at a width per
  layer. A flag routes a stated group of nets as one bus, if detection misses it. Each change gets its own tests in
  KRT's suite and is pushed to the fork.
- **Zener fork** (benagricola/pcb): `nets.layout.json` written beside the board. It holds each net's type and fields,
  its interface instances, its `DiffPair` membership and a `clearance` field on the stdlib net types. Stage 1 is types
  and fields; stage 2 is interfaces. The board venvs need a pcb build with it before phases can select by interface.

## Gates

Each gate is measured before the step it guards is adopted. A failed gate sends the design back to the user with the
numbers.

- **One score:** the search's switch from the clique to the MST change must leave no bench fixture's run score worse,
  and must not lower the fairing core's quick-route closure. A candidate must stay under about 5 us natively.
- **Refine, speed:** a prototype reaches 2,000 moves a second on the core before the full build. The target is 10,000.
- **Refine, result:** the bench in three configurations shows no fixture worse. The core improves its run score and
  quick-route closure against the same script without refine.
- **The loop:** the fairing core, from a clean script with phases, is compared with the organic script's best routed
  board.

## Removal ledger

Everything these designs supersede, the step that removes it, and what replaces it. Nothing here stays behind as a
second way of doing the same thing. Each item is removed in the step that replaces it, never later. Its plan's last task
deletes the code, the tests, the settings, the CLI options and the docs, and adds a migration entry that tells a script
or a `placemat.toml` what to write instead.

| Removed | In step | Replaced by |
|---|---|---|
| Fixed route stages (pairs, islands, classes, main) and their names | 1 | named phases |
| `[route] islands`, `[route] pair_layers`, `route --islands` | 1 | phase `nets` or `connections` with `width`; `pairs = true` with `layers` |
| `[route] net_halos` | 1 | the capture's net `clearance` field |
| Pairs derived from net-class patterns (`pairs.board_pair_list` for selection) | 1 | `DiffPair` instances from `nets.layout.json` |
| The search's own crossing estimate and clique wire in `Scorer`, if the gate passes | 2 | the run score's incremental terms |
| turn.better's own wire and crossing terms | 2 | the run score's incremental change |
| Explore's added congestion term | 2 | congestion as a run-score term |
| The pin study's own crossing weights | 2 | `[score]` weights by net kind |
| Cleanup pass (`cleanup.py`, `_cleanup`, `PartScore`, `NativeCleanupScoring`) and `[cleanup]` settings | 3 | refine |
| Lock (`lock.py`, `<stem>.lock.json`, `placemat lock` and subcommands, `lock --current`, `lock --accept-seed`) | 3 | the snapshot (`<stem>.placement.json`), constraints in the script |
| `freeze` | 3 | constraints in the script |
| `route --adopt` locking the items it joins | 3 | none: kept routes stay, nothing is locked |
| `board.alternative`, `board.unit`, arrangement alternatives, `place.arrangements_max` | 3 | refine of cell members |
| `--rank-remapped`, `explore.rank_remapped`, and the pin study's separate pose search | 3 | coarse refine owns poses, and the pin study runs inside it |
| turn.better on items refine may move | 3 | refine takes those turns. turn.better stays only for turns the script or a stated constraint owns |
| `preview` | 4 | `run --place-only` |
| `--explore SECONDS`, `--focus*`, `--accept`, `--route-best`, `--route-top` | 4 | `run --restarts N`; ranking by phases |
| The studio's explore and lock views of removed features | 3, 4 | views of restarts and the snapshot |
| SKILL.md's multi-command workflow | 4 | one loop: constraints, phases, `run --detach`, `watch --summary` |

What is kept: suggestions, `apply` and `check`; the studio as a viewer; `route --phase` for routing one phase; and
`route --adopt` for keeping copper on purpose.

## Keeping dead code out

1. **The ledger is the checklist.** Each plan ends with a "Remove" task that names its ledger rows. The final review of
   each step checks every row it owns against the code. Each `grep` for a removed name (`lock_digest`, `cleanup`,
   `alternative`, `--explore`, ...) must return only migration notes.
2. **A CLI surface test.** One test lists every command and option `placemat --help` exposes. A removed one must be
   absent, and a new one must be added to the list on purpose.
3. **A settings surface test.** It does the same for every `[section] key` the settings accept. The generated
   settings table is compared against it.
4. **Unused-code check per release:**
   - Python: an unused-code check (vulture, with a short allow list of entry points), run in CI and on every release;
   - Rust: `cargo build` with `-D dead_code` on the native module.

   A finding is fixed or justified in the allow list with a reason.
5. **Docs follow code.**
   - api.md, SKILL.md, capture.md and the migration notes are updated in the same commit as each removal.
   - A docs test checks that no reference doc names a removed command, option or setting outside the migration notes.
6. **No deprecation period.** Placemat's users are the board sessions, and each release notice says what to migrate. A
   removed form is refused with a message naming its replacement, never kept working alongside the new one. That is the
   project's existing rule.

## Release line

- 0.99.x continues for fixes until the first of these lands.
- Each step ships as 0.100.y with the full suite, the bench, a migration section and a release notice to the board
  sessions.
- 1.0 is cut with the user after step 4 and the last ledger row are merged.
